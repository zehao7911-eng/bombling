# GameWave import

Upload BOMBLING.zip with index.html at the archive root. The bundled inline entry also runs directly in ordinary browsers and on GitHub Pages.

The adapter discovers window.neonlib independently of startup. Accepted physical movement, placement and detonation start a room attempt. A real exit or spike death ends it. Automatic respawn prepares the next attempt, and the next committed input starts it. A partial room restored while stationary starts on its next genuine input. Explicit resume of an already airborne checkpoint continues its real attempt.

Only the bombling profile is sent in the cloud envelope. The exact active physical checkpoint stays local in bombling-v1. Stars and flowers merge by maximum, reward flags by union, and local preferences remain local. Other games' storage is never read or uploaded.

A confirmed positive like earns gold seed buds. A successful direct comment earns prism explosion sparks. They remain optional cosmetics, guarded by durable one-time flags. Unsupported registrations hide the prompts. Strings are used for project IDs, unlike callbacks are ignored, and an image-only direct comment may contain an empty string.

The official [GameWave SDK document](https://rg975ojk5z.feishu.cn/wiki/MQg7wMknzieOkukxyWVc4UB0nDh) was rechecked November 8, 2026 and still displays the October 30 revision. Test evidence distinguishes controller checks, optional SDK mocks, native local-host simulation and public-browser play. Actual supported GameWave App import, live social callbacks and physical-device testing remain separate verification steps.
